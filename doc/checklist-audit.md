## 1. 카드 1 (1/5) 결과물 기록 — 논문에서 앱이 될 문장 하나와 사용자가 할 일 세 가지

### ① 앱 한 문장 (BRB-C01 충족)
- **통과 기준 (`BRB-C01`)**: 앱이 돕는 사람, 앱이 하는 일, 논문의 어느 결과를 쓰는지가 한 문장으로 적혀 있다.
- **확정한 한 문장 ("○○인 사람이 △△할 때 이 앱이 □□을 해 준다" & "이 앱은 누구를 어떻게 돕습니다")**:
  > **“AI 코딩 에이전트(Antigravity, Copilot 등)와 협업하는 웹 개발자**[돕는 사람]가 **16초 이상의 응답 대기 시간 동안 에디터를 힐끔거리며 주의가 분산되거나(12.7초 주기 시각적 폴링 91.7%) 장문의 3지선다 모달에서 2번째 옵션만 편향 선택할 때(78.3%)**[상황 & 논문 결과], 이 앱이 **논문의 36회 실측 결과([표 2] 구간별 확률 분포)와 3대 제언 규칙을 써서 ① 대기 구간별 맞춤형 UI·콘솔 검수 가이드와 무폴링 청각 타이머 작동, ② 3지선다 장문 옵션의 '1줄 핵심 + 위험도' 요약 변환, ③ 에러 로그 결합 3~5줄 구조화 프롬프트 생성 및 36회 원자료 실시간 비교를 해 줍니다**[앱이 하는 일].”

### ② 사용자가 앱에서 실제로 할 일 세 가지 (BRB-C02 충족)
- **통과 기준 (`BRB-C02`)**: 그 사람이 앱에서 실제로 할 일 세 가지가 적혀 있다.
  1. **[할 일 1] 대기 시간(초) 입력 및 무폴링(Zero-Polling) 청각 타이머 · 비동기 검수 체크리스트 실행**:
     - 에이전트에게 지시한 작업의 예상 대기 시간(초)을 입력(또는 원클릭 예시 클릭)하여 논문 [표 2]의 3구간 규칙(`0~15초 IDE 주시 80.0%`, `16~30초 화면 검수 54.5%`, `31초+ 화면 검수 66.7%`)에 따른 행동 처방을 확인하고, 완료 비프음 타이머를 돌려 `12.7초` 주기의 시각적 폴링(힐끔거림)을 0회로 줄이며 F12 콘솔·375px 반응형 체크리스트를 완료합니다.
  2. **[할 일 2] 에이전트의 3지선다 장문 모달을 ‘1줄 핵심 + 위험도 뱃지’로 요약·비교하여 중간 옵션 편향(78.3%) 교정하기**:
     - 에이전트가 제시한 3가지 옵션을 입력(또는 논문 속 실제 '혼밥비서' 사례 A/B/C 불러오기)하여, 긴 설명 때문에 2번째 옵션만 누르는 편향(78.3%) 경고를 확인하고 옵션별 핵심 1줄·위험도·적합도 점수를 비교해 최적 옵션을 채택합니다.
  3. **[할 일 3] 에러 로그 결합 ‘4줄 구조화 프롬프트’ 생성 및 내 대기 세션을 논문 원자료(36건)와 실시간 비교·내보내기**:
     - 10분 자체 디버깅 후 파악한 F12 에러 로그와 원하는 UI 흐름을 넣어 4줄 구조화 프롬프트를 생성·복사하고, 내 대기 세션(초, 행동 유형, 모달 선택)을 추가해 논문 원자료 36건 통계와 실시간으로 대조 및 CSV로 다운로드합니다.

## 2. 카드 2 (2/5) 결과물 기록 — 첫 판 제작 및 할 일 3가지 · 예외 방어 실행 결과

### ① 첫 화면 구성 (BRB-C03 충족)
- `index.html` 최상단 첫 화면에 **10번 논문 제목 전문**, **“이 앱은 누구를 어떻게 돕는가” 한 문장 박스**, **사용자가 할 일 3가지 바로가기 카드**를 배치하여 처음 온 사람이 설명 없이 1분 안에 앱의 목적을 이해하고 바로 써 볼 수 있습니다.

### ② 할 일 세 가지를 실제로 해 본 결과 (BRB-C04, BRB-C05 충족)
1. **[할 일 1 실행 결과]**:
   - `12초` 입력 시 ➔ `0 ~ 15초 (단순 수정 구간)` 판정, 논문 실측 **IDE 지속 주시 80.0% (8/10회)** 표시 및 창 전환 중단 가이드 제시.
   - `25초` 입력 시 ➔ `16 ~ 30초 (중간 작업 구간)` 판정, 논문 실측 **화면 검수 54.5% (6/11회)** 및 **시각적 폴링 2회 ➔ 0회 방어(12.3초 주기)** 산출, 무폴링 청각 타이머 카운트다운 및 완료 비프음 정상 작동.
   - `48초` 입력 시 ➔ `31초 이상 (복합 추론 구간)` 판정, 논문 실측 **화면 검수 66.7% (10/15회)** 및 **시각적 폴링 3회 ➔ 0회 방어(12.9초 주기)** 산출.
2. **[할 일 2 실행 결과]**:
   - 논문 세션 #13(식약처 API null 에러 처리) 3지선다 입력 시 ➔ 3번 옵션(158자, 외부 라이브러리 Zod+파일 12개 수정)은 `위험도: 높음(62점)`, 1번 옵션(단순 렌더링 스킵)은 `위험도: 높음(58점)`, 2번 옵션(옵셔널 체이닝 + 0kcal 폴백)은 `위험도: 낮음(92점)`으로 1줄 요약 및 객관적 추천 완료.
3. **[할 일 3 실행 결과]**:
   - 모듈명 + 10분 디버깅 + F12 에러 로그 입력 시 ➔ 4줄 구조화 프롬프트 즉시 생성 및 클립보드 복사 작동.
   - 새 세션(32초, 혼밥비서 화면 검수, 2번째 옵션) 추가 시 ➔ 전체 세션 수 `36건 ➔ 37건`, 16초+ 검수율 `61.5% ➔ 63.0%`로 실시간 재계산 및 CSV 다운로드 작동.
4. **[잘못된 입력(Edge Case) 방어 테스트 결과 (BRB-C05)]**:
   - `빈 값("")`, `음수("-45")`, `0`, `문자열/스크립트("abc<script>")`, `초대형 값("99999")`, `빈 3지선다 옵션` 입력 시 앱이 멈추거나 에러를 내지 않고 상단 `🛡️ 입력값 자동 방어 및 안전 보정 배너`를 띄우며 안전 기본값(10초/25초/60초 및 기본 비교 템플릿)으로 즉시 보정함을 확인 (`node verify-app.js` 100% Pass).
